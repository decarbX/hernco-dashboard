## v1.3 Analytical Object Specs: Fuel per PTO Hour & Fuel per PTO Turn

These are structured as future clickable analytical objects. The static card displays the primary KPI value. Clicking the card opens a drill-down callout panel with the structure below. Do not build the interactive UI yet — this is the data and interpretation schema each KPI must support.

---

### KPI 1: Fuel per PTO Hour

#### Static Card Display
| Field | Value |
|---|------|
| Label | Fuel per PTO Hour |
| Primary Value | `X.X gal/PTO-hr` |
| Context Line | `Y.Y PTO hrs today · Z.Z gal PTO fuel` |
| Status Dot | Green (< baseline) / Amber (±5% of baseline) / Red (> baseline) |

#### Calculation
```
Fuel per PTO Hour = (∑ engine_fuel_rate_lph WHERE is_pto_on = true) / (PTO hours)
Convert L/hr → gal/hr: ÷ 3.785
Aggregate: mean of per-reading fuel rates during PTO state
```

#### Drill-Down Panel Structure (click-to-expand)

**Tab 1: Trend**
- 7-day sparkline of Fuel per PTO Hour (fuel rate during PTO, day-over-day)
- 30-day rolling average overlay line
- Annotated events: calibration changes, fuel line work (Jun 19), derate event (Jun 24)

**Tab 2: Best / Worst Periods**
- Best PTO hour today: lowest fuel rate at full PTO load (time + gal/PTO-hr)
- Worst PTO hour today: highest fuel rate at full PTO load (time + gal/PTO-hr)
- Context: RPM band during each period (high RPM = high flow, expected)
- Context: whether optimizer was installed before or after each period

**Tab 3: Quality Flags**
- % of PTO readings with valid fuel rate (telemetry gaps excluded)
- % of PTO readings flagged: zero-while-running, return > supply
- Flag if PTO fuel rate exceeds engine max rated consumption (possible sensor error)

**Tab 4: Likely Drivers**
- High fuel/PTO-hr correlated with: high RPM PTO, low ambient temp (cold start), PTO load type
- Low fuel/PTO-hr correlated with: low RPM PTO, warm engine, optimizer effect window
- PTO duty type classification: hydraulic pump vs generator vs compressor (different fuel signatures)

**Tab 5: Operational Interpretation**
- Is PTO fuel rate stable or degrading? (trend direction)
- Is the optimizer showing effect during PTO? (before/after comparison if available)
- How does today compare to the 30-day baseline? (% deviation)

**Tab 6: Recommended Action**
- If trending up: inspect PTO-driven accessory load, check for hydraulic bypass, verify optimizer install
- If trending down: document as optimizer performance evidence
- If anomalous spike: cross-reference with ECM fault codes, derate events, fuel quality

### KPI 2: Fuel per PTO Turn

#### Static Card Display
| Field | Value |
|---|------|
| Label | Fuel per PTO Turn |
| Primary Value | `X.X gal/turn` |
| Context Line | `N PTO cycles today · X.X gal total PTO fuel` |
| Status Dot | Green (low cycles, low fuel) / Amber (high cycles, avg fuel) / Red (high fuel/turn) |

#### Calculation
```
1. Detect PTO turns: edge detection on is_pto_on (false → true = turn start, true → false = turn end)
2. For each PTO turn window: sum fuel consumed = trip_fuel_used_l(end) − trip_fuel_used_l(start)
3. Fuel per PTO Turn = (∑ fuel per turn) / (number of turns)
Convert L → gal: ÷ 3.785
```

#### Drill-Down Panel Structure (click-to-expand)

**Tab 1: Trend**
- 7-day sparkline of Fuel per PTO Turn (avg gal/turn, day-over-day)
- Distribution: min/avg/max fuel per turn each day
- Annotated events: calibration changes, fuel line work (Jun 19), derate event (Jun 24)

**Tab 2: Best / Worst Turns**
- Most efficient PTO turn today: lowest gal/turn (timestamp, duration, fuel)
- Least efficient PTO turn today: highest gal/turn (timestamp, duration, fuel)
- Turn duration context: short turns may skew high (cold engine penalty)
- If turn duration < 5 min, flag as "short cycle — may include cold-start fuel penalty"

**Tab 3: Quality Flags**
- % of turns with complete telemetry (no mid-turn gaps)
- % of turns with fuel anomaly flags active
- Flag if turn count is unusually high or low vs 30-day average (±2σ)
- Flag if a turn has zero fuel recorded (possible sensor dropout)

**Tab 4: Likely Drivers**
- High fuel/turn correlated with: long turn duration, high RPM PTO, first turn after cold start
- Low fuel/turn correlated with: short turn duration, warm engine restart, optimizer effect window
- Turn count drivers: number of site visits, number of PTO job starts, operator behavior

**Tab 5: Operational Interpretation**
- Is fuel per turn increasing? (may indicate PTO load growth or engine efficiency loss)
- Is turn count changing? (may indicate shift pattern or job scope change)
- How do turn duration and fuel correlate? (should show linear relationship — deviation is a signal)

**Tab 6: Recommended Action**
- If fuel/turn trending up with stable turn duration: check PTO load, inspect optimizer
- If turn count spiking: review job dispatch logs, operator PTO usage patterns
- If short-cycle penalty visible: evaluate whether PTO warm-up procedure exists
- If fuel/turn dropping: document as optimizer performance evidence, correlate with install date

## v1.3 Formal Calculation & Validation Specs

Each metric is defined with a full calculation pipeline: raw telemetry → exclusion filters → aggregation → comparison → status label. These specs are the single source of truth for how each KPI number is produced.

---

### SPEC 1: Fuel per PTO Hour

#### 1. Formula
```
Fuel per PTO Hour (gal/PTO-hr) =
    (∑ engine_fuel_rate_lph FOR all readings WHERE is_pto_on = true AND passes exclusion filters)
    ÷ (count of included readings)
    ÷ 3.785

This is the mean fuel rate during PTO state, not total fuel ÷ total PTO hours.
Using mean-of-readings avoids distortion from irregular telemetry intervals.
```

#### 2. Required Fields

| Field | Source | Sensor | Status |
|---|------|--------|--------|
| `engine_fuel_rate_lph` | SkyView360 channel 18392 | ST910x Engine CAN | ✅ Working |
| `is_pto_on` | SkyView360 channel 18365 | ST910x Engine CAN | ✅ Working |
| `is_ignition_on` | SkyView360 channel 18364 | ST910x Engine CAN | ✅ Working |
| `rpm` | SkyView360 channel 18363 | ST910x Engine CAN | ✅ Working |
| `reason_code` | SkyView360 channel 18347 | ST910x Context | ✅ Working |
| `fuel_flow_quality_telemetry_gap` | SkyView360 channel 18841 | ORBCOMM Derived | ✅ Working |
| `fuel_flow_quality_zero_running` | SkyView360 channel 18842 | ORBCOMM Derived | ✅ Working |
| `fuel_flow_quality_return_gt_supply` | SkyView360 channel 18843 | ORBCOMM Derived | ✅ Working |

#### 3. Units
- **Input:** `engine_fuel_rate_lph` (L/hr)
- **Output:** gal/PTO-hr (÷ 3.785)
- **Display precision:** 1 decimal place (X.X gal/PTO-hr)
- **Internal precision:** 4 decimal places (for trend comparison)

#### 4. Exclusion Filters
Readings excluded from calculation:

| Exclusion | Rule | Reason |
|---|------|--------|
| EXCL-01 | `is_ignition_on = false` | No engine operation, PTO state invalid |
| EXCL-02 | `is_pto_on = false` | Not a PTO reading |
| EXCL-03 | `engine_fuel_rate_lph ≤ 0` | Zero or negative fuel rate (sensor dropout, ignition-off PTO residual) |
| EXCL-04 | `engine_fuel_rate_lph > 120` | Exceeds maximum rated fuel consumption for this engine class (~120 L/hr). Probable sensor error. |
| EXCL-05 | `fuel_flow_quality_telemetry_gap = true` | Telemetry gap — reading may be interpolated, not measured |
| EXCL-06 | `fuel_flow_quality_zero_running = true` | Fuel reported as zero while engine running — sensor dropout |
| EXCL-07 | `fuel_flow_quality_return_gt_supply = true` | Return flow exceeds supply — sensor inversion, unreliable |
| EXCL-08 | `rpm < 400` | Below idle threshold — engine not under PTO load |
| EXCL-09 | `rpm > 4000` | Above redline for this engine class — probable sensor spike |

#### 5. Quality Thresholds
After exclusions applied:

| Quality Level | Criteria | Label |
|---|------|-------|
| **Good** | ≥ 90% of PTO readings pass exclusions, ≥ 30 PTO readings in period | 🟢 High confidence |
| **Fair** | 70–89% of PTO readings pass exclusions, OR 15–29 PTO readings | 🟡 Moderate confidence |
| **Low** | < 70% pass rate, OR < 15 PTO readings, OR IFM sensors non-functional | 🔴 Low confidence — CAN-only fuel estimate |

Note: For Station 1983 specifically, IFM flow sensors are non-functional. All PTO fuel metrics carry an automatic "CAN-only fuel estimate" caveat regardless of quality level until IFM sensors are repaired.

#### 6. Baseline Period
| Parameter | Value |
|---|-------|
| **Primary baseline** | Trailing 30 days (rolling window) |
| **Secondary baseline** | Same day last week (day-over-day) |
| **Minimum baseline** | 5 PTO-active days required; if fewer, show "Insufficient baseline data" |
| **Excluded from baseline** | Days with zero PTO activity, days with derate events, days with < 15 PTO readings |

#### 7. Event Annotations
Events overlaid on trend sparkline and flagged in drill-down:

| Event | Date | Annotation |
|---|------|-------------|
| Optimizer install | TBD | Vertical marker — "Optimizer installed" |
| Fuel line work | Jun 19, 2026 | Orange marker — "Fuel line reconfiguration" |
| ECM derate event | Jun 24, 2026 | Red marker — "Derate — PTO data excluded" |
| Calibration change | TBD | Blue marker — "Sensor recalibration" |
| IFM sensor repair | TBD | Green marker — "IFM flow sensors restored" |

#### 8. Status Labels

| Status | Criteria | Color | Meaning |
|---|------|-------|---------|
| **Efficient** | Fuel/PTO-hr ≤ (30-day baseline − 5%) | 🟢 Green | Below baseline — potential optimizer effect |
| **Stable** | Fuel/PTO-hr within ±5% of 30-day baseline | 🔵 Blue | Normal operating range |
| **Elevated** | Fuel/PTO-hr > (30-day baseline + 5%) AND ≤ (baseline + 15%) | 🟡 Amber | Above normal — monitor |
| **High** | Fuel/PTO-hr > (30-day baseline + 15%) | 🔴 Red | Significantly above baseline — investigate |
| **Insufficient** | < 5 PTO-active days in baseline OR < 15 readings today | ⚪ Grey | Not enough data to calculate status |

### SPEC 2: Fuel per PTO Turn

#### 1. Formula
```
Step 1: Detect PTO turns
    A PTO turn begins when is_pto_on transitions false → true
    A PTO turn ends when is_pto_on transitions true → false
    A turn is valid if: start-to-end duration ≥ 30 seconds AND end has a matching is_ignition_on reading

Step 2: Calculate fuel per turn
    For each valid turn window [t_start, t_end]:
        fuel_this_turn = trip_fuel_used_l(at t_end) − trip_fuel_used_l(at t_start)
        IF fuel_this_turn ≤ 0 → exclude turn (sensor dropout or trip reset)

Step 3: Aggregate
    Fuel per PTO Turn (gal/turn) = (∑ fuel_this_turn for all valid turns) ÷ (count of valid turns) ÷ 3.785
```

#### 2. Required Fields

| Field | Source | Sensor | Status |
|---|------|--------|--------|
| `is_pto_on` | SkyView360 channel 18365 | ST910x Engine CAN | ✅ Working |
| `is_ignition_on` | SkyView360 channel 18364 | ST910x Engine CAN | ✅ Working |
| `trip_fuel_used_l` | SkyView360 channel 18836 | ST910x Engine CAN | ✅ Working |
| `reason_code` | SkyView360 channel 18347 | ST910x Context | ✅ Working |
| `rpm` | SkyView360 channel 18363 | ST910x Engine CAN | ✅ Working |
| `fuel_flow_quality_telemetry_gap` | SkyView360 channel 18841 | ORBCOMM Derived | ✅ Working |

#### 3. Units
- **Input:** `trip_fuel_used_l` (L, cumulative)
- **Output:** gal/turn (÷ 3.785)
- **Display precision:** 1 decimal place (X.X gal/turn)
- **Internal precision:** 4 decimal places

#### 4. Exclusion Filters

| Exclusion | Rule | Reason |
|---|------|--------|
| EXCL-T01 | Turn duration < 30 seconds | Too short to be a real PTO cycle — likely noise or momentary switch flutter |
| EXCL-T02 | Turn duration > 8 hours | Unrealistically long — likely sensor stuck in PTO state |
| EXCL-T03 | `fuel_this_turn ≤ 0` | Zero or negative fuel delta — trip meter reset or sensor dropout |
| EXCL-T04 | `fuel_this_turn > 100` gallons | Implausible single-turn fuel consumption for this engine class |
| EXCL-T05 | Turn contains a `fuel_flow_quality_telemetry_gap` reading | Mid-turn telemetry gap — fuel delta unreliable |
| EXCL-T06 | `is_ignition_on = false` at turn start or end | PTO state change during ignition-off is invalid (sensor residual) |
| EXCL-T07 | Turn overlaps a `reason_code = Startup` event | Turn spans an ignition cycle boundary — fuel delta may include non-PTO consumption |

#### 5. Quality Thresholds

| Quality Level | Criteria | Label |
|---|------|-------|
| **Good** | ≥ 5 valid PTO turns today, ≥ 90% of raw turns pass exclusions | 🟢 High confidence |
| **Fair** | 3–4 valid turns, OR 70–89% pass rate | 🟡 Moderate confidence |
| **Low** | < 3 valid turns, OR < 70% pass rate | 🔴 Low confidence |

Note: Station 1983 carries the same CAN-only fuel caveat as Spec 1 until IFM sensors are repaired.

#### 6. Baseline Period
| Parameter | Value |
|---|-------|
| **Primary baseline** | Trailing 30 days (rolling window) |
| **Secondary baseline** | Same day last week (day-over-day) |
| **Minimum baseline** | 10 valid turns across ≥ 5 PTO-active days; if fewer, show "Insufficient baseline data" |
| **Excluded from baseline** | Days with zero valid turns, days with derate events, days with < 3 valid turns |

#### 7. Event Annotations
Same annotation set as Spec 1 (Section 7 above). Additional turn-specific annotations:

| Event | Date | Annotation |
|---|------|-------------|
| First turn after cold start | Per occurrence | Marker on first turn each day — "Cold start penalty window" |
| Consecutive short cycles | Any day | Flag if ≥ 3 turns < 5 min duration — "Possible operator pattern" |

#### 8. Status Labels

| Status | Criteria | Color | Meaning |
|---|------|-------|---------|
| **Efficient** | Fuel/turn ≤ (30-day baseline − 10%) | 🟢 Green | Below baseline — potential optimizer effect |
| **Stable** | Fuel/turn within ±10% of 30-day baseline | 🔵 Blue | Normal operating range |
| **Elevated** | Fuel/turn > (30-day baseline + 10%) AND ≤ (baseline + 25%) | 🟡 Amber | Above normal — check for load change |
| **High** | Fuel/turn > (30-day baseline + 25%) | 🔴 Red | Significantly above baseline — investigate |
| **Insufficient** | < 10 valid turns in baseline OR < 3 valid turns today | ⚪ Grey | Not enough data |

Note: Fuel per PTO Turn uses wider thresholds (±10% / ±25%) than Fuel per PTO Hour (±5% / ±15%) because turn-level aggregation has higher natural variance.
